# Inventor 組立ファイル（.iam）の構造解析

`samples/iam/Assembly_全体_Φ54.5.iam`（Inventor 2026、部品 10 種類・39 か所）を、同じ組立を Inventor で書き出した
`samples/stp/Assembly_全体_Φ54.5.stp` と突き合わせて調べた結果。
読み取りは `app/src/formats/iam/index.js`、評価は `app/test/assembly.test.mjs`。

## 1. 結論

- .iam も .ipt と同じ **OLE2（CFB）＋ RSe セグメント（Zstandard 圧縮）** で、.ipt の読み取り（`app/src/formats/ipt/container.js`）をそのまま使える
- **形状（B-rep）は持たない**。部品の形状は参照先の .ipt にある（`AmBREPSegment` は 623 バイトで、形状を含まない）
- 表示に必要な 3 つを読み取れた

  | 情報 | 場所 | 内容 |
  |---|---|---|
  | 参照するファイル | ストリーム `UFRxDoc` | 部品ファイルのフルパス。Content Center の部品は表示名つき |
  | 出現（部品を置いた 1 か所）の名前 | `AmDcSegment` | 「部品名:番号」（Inventor のモデルブラウザーの表示名） |
  | 出現の配置 | `AmRxSegment` | 印付きの 4×4 行列（剛体変換、単位 cm） |

- **STEP との照合**: 39 か所の出現の名前・並び・部品・配置が全て一致した（配置の成分の差は最大 5.1e-13 mm）

## 2. ファイル構造

| セグメント | 展開後の大きさ | 使い道 |
|---|---:|---|
| `AmRxSegment` | 277,757 B | 出現の配置（§5）。拘束などもここにあると考えられるが、読んでいない |
| `AmDcSegment` | 183,783 B | 出現の名前（§4） |
| `AmAppSegment` | 49,113 B | 読んでいない |
| `AmGraphicsSegment` | 31,288 B | 読んでいない（表示用のキャッシュと考えられる） |
| `AmBrowserSegment` | 19,572 B | 読んでいない（出現名はここにもあるが、配置との対応は AmDcSegment で取れた） |
| `FBAttributeSegment`・`DesignViewSegment`・`NBNotebookSegment` | 1,378・391・139 B | 読んでいない |
| `AmBREPSegment` | 623 B | 形状は含まない |

ほかに、ストリーム `UFRxDoc`（ファイル参照、§3）、サムネイル（.ipt と同じ場所の PNG）、プロパティセット（iProperties）がある。

## 3. ファイル参照（ストリーム `UFRxDoc`）

文字列は「文字数（UInt32）＋ UTF-16LE」で並ぶ。拡張子が .ipt・.iam などの文字列がファイルのフルパス。

- **先頭は組立自身のパス**（参照先ではない）。この規則はサンプル 1 つでしか確かめていない
- Content Center の部品は、パスの直後に `Content Center Files`、その次に**表示名**が続く。
  例: `C:\ProgramData\Autodesk\Inventor 2026\Content Center\Libraries\ja-JP\JIS B 1176\JIS B 1176 - M4 x 8 - 0.7.ipt`
  → `Content Center Files` → `JIS B 1176 - メートル M4 x 8`
- 出現名の部品名は、ファイル名（拡張子なし）か、この表示名になる（§6）
- パスには**保存した PC のユーザー名を含むフォルダ名**が記録される（サンプルを配布するアプリに埋め込むときは注意）

## 4. 出現名（`AmDcSegment`）

1 件 = `[ID: UInt32][0x30000002][0: UInt32][文字数: UInt32][名前: UTF-16LE]`。名前は「部品名:番号」（例 `A1_円筒_両切欠き＋片ネジ_Φ54.5:2`）。

- セグメント内の**並びの順は、モデルブラウザーの順**（STEP の出現の順とも一致）
- **ID の順は、作成の順**（配置の並びと対応する。§6）
- 同じ 8 バイト（`0x30000002`・`0`）の並びは、原点の作業フィーチャの名前（`YZ Plane`・`X Axis`・`Center Point` など 7 件）や、
  名前ではないバイナリの中にも現れる（サンプルでは計 131 件）。`名前:数字` の形のものだけを拾うと、出現の 39 件がちょうど残る

## 5. 配置（`AmRxSegment`）: 印付きの 4×4 行列

行列は行優先の 16 成分（`[R | t; 0 0 0 1]`、t は cm）。値が 0 や 1 の成分は省かれ、先頭の 4 バイトの印で示す。

| 位置 | 内容 |
|---|---|
| 0–1 バイト（UInt16） | 値が **1** の成分（ビット i ↔ 成分 i = 4 × 行 + 列） |
| 2–3 バイト（UInt16） | 値が **0** の成分 |
| 続き | 残りの成分だけが倍精度（Float64）で成分の順に並ぶ |

例: 回転なしで移動だけの配置は、1 の成分が対角（ビット 0・5・10・15 → `0x8421`）、0 の成分が回転の非対角と 4 行目
（ビット 1・2・4・6・8・9・12・13・14 → `0x7356`）で、残りの 3 成分（移動量）だけが倍精度で続く。

配置の見つけ方: セグメント全体から、4 行目が `0 0 0 1`（1 の印のビット 15、0 の印のビット 12〜14）で、
読み出した行列が剛体変換（回転部分が正規直交で行列式 +1、移動量が有限）になるものを拾う。
レコード全体の構造は分かっていない（この探し方で、サンプルでは出現と同じ 39 個がちょうど見つかる）。

## 6. 出現と配置の対応づけ

- **出現名を ID の順に並べると、配置の並びと 1 対 1 に対応する**（どちらも作成の順）
- 表示の順は出現名の並び（モデルブラウザーの順）に戻す
- 部品は、出現名の「部品名」を参照ファイルの名前（拡張子なし）か Content Center の表示名と照らして決める
- 出現と配置の数が合わないとき（未知の版や構造）は対応づけられないので、アプリは部品を原点に置いて知らせる

照合（`app/test/assembly.test.mjs`）: 名前・並び・部品・配置が STEP と一致。部品の形状は samples/ipt の .ipt から読み、
ボルト 20 本の軸が組み付け先の部品のねじ穴の軸と一直線になることも確かめている（形からの独立な確認）。

## 7. アプリでの参照先の探し方

.iam には形状が無いので、参照先の .ipt を次の順で探す（ファイル名で照合、大文字小文字は区別しない）。

1. 一緒に受け取ったファイル（ドラッグ＆ドロップ・ファイル選択・起動ファイル）。
   起動ファイルに .iam をドロップすると、**同じフォルダの .ipt も一緒に**アプリへ送る
2. アプリに埋め込んだサンプル（samples/ipt）

見つからない部品は「見つからない部品」に保存先のパスとともに挙げ、その .ipt を画面にドロップすると組立に加わる。

## 8. 分かっていないこと

サンプルに無いため、次は確かめていない（**分からない**）。

- 拘束（合わせ・挿入など）の記録。配置は拘束を解いた結果の行列として読んでいる
- 出現の表示・抑制の状態、レベル オブ ディテール、ポジション表現、フレキシブル
- サブアセンブリ（.iam の中の .iam）とパターン。サブアセンブリの配置が親の座標か、部分組立の座標か
- 参照の先頭が組立自身であることが、ほかのファイルでも成り立つか

## 9. 同じ組立の STEP（AP214）

STEP は形状と配置を全て含むので、それだけで組立を表示できる（`app/src/formats/step/`）。

- 書式: ISO 10303-21。複合エンティティ、`\X2\…\X0\`（UTF-16）の文字列、行をまたぐ文字列を読む
- 組立: `NEXT_ASSEMBLY_USAGE_OCCURRENCE` と `CONTEXT_DEPENDENT_SHAPE_REPRESENTATION`（`ITEM_DEFINED_TRANSFORMATION`、
  配置 = F(親の座標系)・F(子の座標系)⁻¹）をたどる
- 形状: `MANIFOLD_SOLID_BREP` の面（平面・円筒・円錐・トーラス・球）と稜線（直線・円・楕円・B スプライン（有理を含む））
- 単位: `GLOBAL_UNIT_ASSIGNED_CONTEXT` の長さ・角度の単位。材質と密度は `PROPERTY_DEFINITION('material property')` から
  （`DERIVED_UNIT` の g/cm³ を g/mm³ に直す）

.ipt との照合: 同じ部品 8 種類で、外形・座標の範囲・円筒（ねじ情報を除く）・円錐・面の数・種数・材質・密度が一致し、
三角形分割から求めた体積の差は外接箱の体積の 0.2% 以内。.ipt の iProperties の材質・密度（[ipt-format.md](ipt-format.md) §3）も STEP と一致した。
