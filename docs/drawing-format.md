# 2D の図面（DWG・DXF・PDF・Jw_cad・SXF）と PDF の 3D の読み取りと表示

AutoCAD・Inventor などが書いた 2 次元の図面（.dwg・.dxf）と、図面の PDF（3D を含む PDF も）、Jw_cad の図面（.jww）、SXF（国土交通省の電子納品の図面。.sfc・.p21）を、Inventor・AutoCAD・Acrobat が無くても、
このアプリの中だけ（JavaScript）で読み、Canvas に描く（PDF の 3D は 3D の表示に出す）。読み取りは仕様書（Open Design Alliance の
*Open Design Specification for .dwg files*・Autodesk の *DXF Reference*・ISO 32000-1（PDF 1.7）・ECMA-363（U3D））から自前で書いた
（GPL のライブラリは使わず、コードも写していない）。PDF の圧縮（Flate）だけは、同梱の fflate（MIT）で解く。
PDF は 6 章、PDF の 3D は 7 章、Jw_cad は 8 章、SXF は 9 章。

## 1. 構成

| 場所 | 役割 |
|---|---|
| `formats/dwg/` | DWG のビット列（`bits.js`）・ファイルの節（`file.js`: R13〜R2000 の節の地図、R2004 以降の暗号化した見出し・ページの地図・LZ77 の圧縮）・見出しの変数（`header.js`: 線種の尺度・単位など）・クラスとオブジェクトの地図（`sections.js`）・オブジェクト（`objects.js`: 図形 30 種類ほどと、画層・線種・文字スタイル・ブロック・レイアウト）。R2007 は `rs2007.js`（まだ） |
| `formats/cad2d/` | DWG と DXF で共通の **図面のモデル**（`model.js`）。DXF の読み取り（`from-dxf.js`: ASCII・バイナリ）、DWG のオブジェクトの組み立て（`from-dwg.js`）、図面に固有の曲線（`curves.js`: 通過点のスプライン・膨らみ・OCS）、入口（`index.js`） |
| `viewer2d/` | 描くもの（`scene.js`: ブロックの入れ子・画層ごと／ブロックごとの色・線種・線の太さ・ハッチングの模様・ビューポート）、Canvas への描画（`viewer2d.js`）、指した図形の索引（`hit.js`）、説明（`describe.js`）、文字の書式（`text.js`）、色番号（`colors.js`） |
| `formats/pdf/` | PDF の字句と値（`objects.js`）・ストリームの符号化（`filters.js`）・ファイルの構造（`file.js`: 相互参照・オブジェクトのストリーム・壊れた相互参照の読み直し・ページの木・画層）・書体と文字の対応（`fonts.js`）・色（`colorspace.js`）・ページの中身の実行（`content.js`）・画像（`images.js`）・注記の見た目（`annotations.js`）・3D の取り出し（`three-d.js`）。図面のモデルにするのは `cad2d/from-pdf.js` |
| `formats/jww/` | Jw_cad の図面（MFC の CArchive）の見出し・画層グループ・色・線種・図形・ブロックの定義（`index.js`）。図面のモデルにするのは `cad2d/from-jww.js` |
| `formats/sxf/` | SXF の SFC（注記の中のフィーチャの並び。`index.js`）と P21（AP202 の実体を SFC と同じフィーチャの並びに直す。`p21.js`）、共通の表（色・線種・線幅・用紙・矢印。`tables.js`）。図面のモデルにするのは `cad2d/from-sxf.js` |
| `formats/u3d/`・`formats/model3d.js` | U3D（ECMA-363）のビット列と算術符号（`bitstream.js`）・段階的なメッシュ（`clod.js`）・場面の組み立て（`index.js`）。3D の表示のメッシュと部品の一覧にするのは `model3d.js` |

形式の判定は中身で行う（DWG は先頭の版の印 `AC10xx`、DXF は `0 / SECTION` かバイナリの印、PDF は先頭 1 KB の `%PDF-`、JWW は先頭の `JwwData.`、SXF は ISO 10303-21 の見出しの `SCADEC`・`ASSOCIATIVE_DRAUGHTING`。3D の STEP と同じ外枠なので、見出しで分ける）。拡張子が違っても開ける。

## 2. 読める版

| 版（AutoCAD の年） | DWG | DXF |
|---|:-:|:-:|
| R12 以前（〜1992） | ✗（保存し直しを案内する） | ✓ |
| R13・R14（1994〜1997） | ✓ | ✓ |
| R2000（2000〜2002） | ✓ | ✓ |
| R2004（2004〜2006） | ✓ | ✓ |
| R2007（2007〜2009） | ✗（未対応。Reed–Solomon の符号と別の圧縮。次の課題） | ✓ |
| R2010・R2013・R2018（2010〜） | ✓ | ✓ |

DXF の文字コード: R2007 以降は UTF-8、それより前は `$DWGCODEPAGE`（ANSI_932 なら Shift_JIS）。`$DWGCODEPAGE` が無い DXF
（Jw_cad の書き出しなど）は中身から推す（UTF-8 として正しければ UTF-8、Shift_JIS として正しく日本語の文字があれば Shift_JIS、それ以外は Windows-1252）。DWG は R2004 まで文字コードの番号、
R2007 以降は UTF-16。どちらも `\U+XXXX`・`\M+NXXXX`（文字の逃がし）を文字に戻す。

## 3. 確かめ方（評価関数）と結果

独立した答えと突き合わせる。

1. **AutoCAD 自身の値**（`program/tools/dwg-check.mjs`）: LibreDWG の試験データには、AutoCAD が図形の値を書き出した一覧（VLA の `.txt`）が
   付いた図面がある。読んだ値（中心・半径・始点・文字・画層・線の太さなど）を 1 つずつ比べる。
   **結果: 112 ファイル・オブジェクト 88,955 個を読み、読めなかったのは R2007 の 1 ファイルだけ。値は 825/843 が一致**
   （残り 18 は、DWG が通過点しか持たないスプライン。生のオブジェクトの段階では制御点が無いため。4 で解いた）
2. **DWG と DXF の突き合わせ**（`program/tools/cad2d-check.mjs`。比べ方は `cad2d-compare.mjs` で、試験と共用）: 同じ図面を AutoCAD が
   2 つの形式で書いた対（ハンドルが同じ）を、DWG の読み取りと DXF の読み取りでそれぞれ図面のモデルにし、図形ごとに全ての値を比べる。
   2 つの読み取りは独立（ビット列と文字の群）なので、合えば両方が正しい見込みが高い。
   **結果: 56 対（R2007 と R12 以前の 24 対を除く）・図形 49,152/49,188 が一致**。残り 36 の内訳と原因:
   - 線の太さ 31（DWG は「既定」、DXF は省略 = 「画層ごと」）: AutoCAD の一覧がある図面では DWG の読みと AutoCAD が一致する。
     この 2 つの図面には一覧が無く、どちらが AutoCAD の意図かは **分からない**（どちらも細線で、見た目の差は小さい）
   - 寸法の文字 " "（空白 1 つ = 文字を出さない）2・引出線の点 1・画層 1・ブロック 1: DXF が別の保存（後の版）だったもの、
     AutoCAD が DXF に書くときに足すもの（引出線の注記の手前のフック線）
3. **ezdxf（MIT）との比較**: DXF の読み取りの図形の数を ezdxf と比べた（バイナリの DXF を含む）。
4. **通過点のスプライン**: DWG は通過点と端の接線しか持たないことがある。AutoCAD の DXF には AutoCAD が計算した制御点がある。
   **AutoCAD の計算を再現した**: ノットは通過点の間の弦の長さの累積、端の接線があれば 1 階微分 = 接線（5 で長さも使うと分かった）、
   無ければ 2 階微分 = 0。
   許容差 0 の 19 本で、制御点・ノットが相対 1e-15 で一致。許容差 > 0 の 1 本（許容差 1.0）は AutoCAD が近似して通過点を外れる
   （最大 1.0）ので厳密には再現できないが、曲線どうしの差は 0.54（許容差の内）
5. **ネットの無料の素材**（[ACadSharp](https://github.com/DomCR/ACadSharp) の試験の図面。MIT）: 同じ図面を AutoCAD が R14〜R2018 の
   DWG と DXF（ASCII・バイナリ）で保存した組。2 の道具で突き合わせた。**結果: R2000・R2004・R2010・R2013・R2018 の全てで
   図形 310 個のうち 307〜308 が一致**（R14 の DWG は対の DXF が無いので、読めること・失敗 0 だけを確かめた。R2007 はまだ読めない）。残りは、AutoCAD が保存のたびに作り直す注釈の無名のブロック（参照先のハンドルが変わる）、
   引出線のフック線（下の 5 章）、R2013 以降の DWG が通過点を持ち DXF が持たないスプライン 1 本（制御点は一致）。
   この突き合わせで見つけて直した誤り:
   - **色見本帳の色**（RAL などの名前つきの色。R2004+）: RGB は図形に無く、ハンドルの先の DBCOLOR にある。図形の中で RGB を
     読もうとして、続く値（線種の尺度・中心・半径）が全てずれていた（円が y = 6×10⁶² に飛び、図面全体が点に縮んで見えた）
   - **通過点のスプラインの端の接線の長さ**: 長さも微分の値に使う（AutoCAD の制御点 = 端 ± 接線 / 3。等間隔のノットの例）。
     これまで単位ベクトルにしていた（AutoCAD の多くの図面は単位ベクトルで持つので、4 の 19 本は変わらず一致）
   - **DXF の文字列のキャレット表記**: 改行などの制御文字は `^J` のように書かれる（`^ ` は ^ そのもの）。解いていなかった
   - **R2018 の複数行の属性**: DXF の属性の後ろに、埋め込みの MTEXT の値（`101 Embedded Object` から）が同じグループコードで続く。
     属性の幅の係数・揃え・反転の値と取り違えていた
   - 描けない値の図形（大きさが数でない円など）が 1 つあると、表示全体が止まった。その図形だけ飛ばし、右の欄に数を出す
6. **見出しの変数**（`formats/dwg/header.js`。`$LTSCALE`・`$INSUNITS` など）: 変数は決まった順に詰めて並び（版ごとに有る・無いが変わる）、
   欲しい `$INSUNITS` は先頭から 289 番目なので、その前を全て型どおりに読み飛ばす。並びは仕様書の表を ACadSharp（MIT）の読みと突き合わせて作り、
   5 の見本の **R2000・R2004・R2010・R2013・R2018 の見出しの節を読んだ値を、同じ図面の DXF の 12 個の変数と比べた。全て一致**
   （範囲 `$EXTMIN`・`$EXTMAX`、日時 `$TDUCREATE`・`$TDUUPDATE`・`$TDINDWG` のような既定でない値を含むので、並びが 1 つずれれば合わない。
   試験では HANDSEED を 1 つ抜くと落ちることを確かめた）。R14 は対の DXF が無いので、範囲・文字の高さが R2000 以降と同じ値になることだけを確かめた。
   - DWG の日時は**世界時**で、DXF の `$TDCREATE`（地方時）ではなく `$TDUCREATE` と一致する（見本では 1 時間違う）。最初は値の大きさに比べた
     幅（1e-6 の比）で比べて「一致」としていたが、ユリウス日（約 246 万）では 2 日を超えるずれまで通る幅だった。ミリ秒で比べ直して分かった
   - 限界: 隣り合う同じ型の変数が同じ値のとき（見本の `$TDINDWG` と `$TDUSRTIMER`）は、入れ替わっていても値では見分けられない
   - 読めなければ、図形は描き、線種の尺度 1・単位なしとして描いて、見出しバーで知らせる（図形の失敗とは数えない）
7. **試験**（`program/tests/js/drawing.test.mjs`・`dwg-header.test.mjs`）: 同梱のサンプルの図面を、ASCII（UTF-8・Shift_JIS）・バイナリの DXF と、
   DWG（R2000・R2004。LibreDWG の `dxf2dwg` で変換したもの）で読み、図形ごとに突き合わせる。AutoCAD の制御点の再現は、AutoCAD が書いた
   DXF の値を試験の中に持つ。見出しの変数は、5 の見本の見出しの節だけを抜き出した素材（`tests/fixtures/drawings/dwg-header/`）で比べる

評価の題材（LibreDWG の試験データ）は使用条件がはっきりしないので、リポジトリには入れない。手元で確かめるときは
`git clone --depth 1 https://github.com/LibreDWG/libredwg` の `test/test-data` を道具に渡す。

```sh
node program/tools/dwg-check.mjs  libredwg/test/test-data/{.,2000,2004,2010,2013,2018,r14}   # AutoCAD の値と比べる
node program/tools/cad2d-check.mjs libredwg/test/test-data                                    # DWG と DXF を突き合わせる（--verbose で全ての違い）
python program/tools/make_drawing_sample.py                                                    # サンプルと試験の図面を作り直す（pip install ezdxf）
```

突き合わせで見つけて直した誤り（記録）: R2000 の紙空間の図形を空間の印だけで集めていた／ハンドルの相対の参照（+n・−n）を
絶対として読んでいた（AutoCAD は絶対で書くことが多く、LibreDWG の書いた図面で表に出た）／R2000 の属性・頂点を
「最初〜最後のハンドル」で引いていなかった／DWG の無名のブロック（*D・*U）は番号を持たないので、読み取りが振る（比べるときは
ブロックの記録のハンドルで比べる）。

## 4. 表示

- 線は「色・太さ・破線」ごとに 1 つの Path2D にまとめ、拡大・移動は変換だけで描き直す（4.7 万図形の図面で、組み立て 90 ms ほど）
- 座標は外形の中心を原点にずらして持つ（大きな座標でも、Canvas の単精度で崩れない）
- 色: 色番号（ACI）は規則（色相 15° × 明るさ 5 段 × 彩度 2 段、切り捨て）で作る。色番号 7 は地に合わせて白か黒。
  地とのコントラスト比が 3 に届かない色（白地のシアン・黄・緑）は、色相を保って前景の側へ寄せる（`--sheet-contrast`）。
  ezdxf の表とは 240 色中 201 色が一致し、残りは中間の値の ±1 か、ezdxf の表の不規則な値（AutoCAD 本体の値は確かめていない）
- 線種: `$LTSCALE` × 図形の尺度 × ブロックの尺度。画面で 1 周期が 3 px より短ければ実線（無駄な描画と縞模様を避ける）
- 線の太さ: 0.25 mm 以下は 1 px、0.50 mm で 2 px（AutoCAD の表示と同じ考え方）。ツールバーで切れる
- 文字: SHX・TrueType の字形の代わりに画面の書体（`--font-drawing`）で描く。高さ = 大文字の高さ。TEXT の揃え（左・中・右・
  2 点の間に収める）・MTEXT の折り返し・書式の符号（`\P`・`{\f…;}`・`%%c` → ⌀ など）を解く
- ブロック参照: 入れ子・尺度・回転・鏡映・押し出し（OCS）・配列（MINSERT）・属性。画層 0 の図形はブロック参照の画層・色を受け継ぐ
- 寸法: 寸法の見た目のブロックを描く。DWG で寸法にブロックが無いもの（AutoCAD が DXF に書くときに作るもの）は、定義点から簡単に描く
- ハッチング: 塗り潰し・グラデーション（最初の色で塗る）・模様（境界で切った線分。細かすぎる模様は薄い塗りにする）
- レイアウト: 紙の図形と、ビューポートの中のモデル（枠で切る）。最初のビューポート（紙そのもの）は描かない
- 指した図形: 種類・寸法（長さ・半径・中心角・頂点の数・文字・ブロック名・寸法の値）・画層を読み出しに出し、青く強調する。
  画層の行にカーソルを合わせると、その画層の図形をまとめて強調する

## 5. まだできないこと（次の課題）

- **R2007 の DWG**（AutoCAD 2007〜2009 の形式）。いまは「保存し直し」を案内する
- まだ描かない図形: マルチ引出線・表・マルチライン・ワイプアウト・幾何公差・弧長寸法・ラスター画像・3D ソリッド・リージョン など
  （読み飛ばし、右の欄に種類と数を出す）
- 引出線の注記の手前のフック線（DWG には点として無く、寸法スタイルの矢印の大きさで AutoCAD が作る）・寸法スタイルの値
  （矢印の大きさ・文字の高さ）を使った描き直し
- SHX・TrueType の字形そのもの（文字の幅は書体によって違う）
- Inventor の図面（.idw）。.idw は Inventor の独自形式で、図面のビューは Inventor が 3D から計算して持つ。Inventor から DWG に
  書き出せば開ける

## 6. PDF の図面

PDF には円も寸法も無く、線と曲線の「パス」・文字・画像だけがある。ページを紙のレイアウト（`*Page1` …）にし、画層（Optional Content。
CAD が PDF に書き出すときの画層）を画層にして、DWG・DXF と同じ図面のモデル・同じ表示で見せる。座標はページの左下を原点にした mm
（1 pt = 25.4 / 72 mm。ページの回転 `/Rotate` も入れる）。

### 6.1 読めるもの

- ファイル: 相互参照の表・ストリーム（PDF 1.5〜）・両方の混ざったもの・更新を重ねたもの（`/Prev`）・オブジェクトのストリーム。
  相互参照が壊れていれば、ファイルを走査して `n 0 obj` を拾い直す（見出しバーで知らせる）。暗号化した PDF は読めないと知らせる
- 符号化: Flate・LZW・ASCIIHex・ASCII85・RunLength と予測子（TIFF・PNG）。Flate の終わりが壊れていても、そこまでに解けた分を使う
- 描くもの: パス（直線・3 次ベジェ・長方形）・塗り（nonzero・evenodd）・線の太さ・破線・端の形・透明度・切り取り（外形で近似）、
  文字（Type1・TrueType・Type3・CID の書体、ToUnicode・定義済みの CMap（Shift_JIS・EUC・UCS2・UTF16 の横書き・縦書き）、送り幅）、
  画像（JPEG はそのまま・それ以外は画素に。インラインの画像・透明度のマスク）、Form XObject、注記の見た目（見た目の無い朱書きの
  注記やフォームの欄は、種類から作る）、色空間（Gray・RGB・CMYK・Indexed・Separation・DeviceN・Lab・ICCBased・関数 0・2・3・4）
- ページの名前（`/PageLabels`。i・ii・1・2…）を、ページのタブ・送りの名前にする
- ページの中身は、そのページを初めて表示するときに読む（117 ページの PDF も、開くのは最初のページを読む時間だけ）。
  開くときは 3D の注記だけを集める

### 6.2 確かめ方（評価関数）と結果

1. **MuPDF の描いた絵と画素で比べる**（`program/tools/pdf-check.mjs`・`pdf_reference.py`。PyMuPDF は評価にだけ使い、アプリには入れない）:
   紙を同じ大きさの画像に描き、インクの画素（紙の色との差が 40 を越える画素）が、相手のインクの 2 px の内にあるかを数える。
   「余計に描かない」= こちらのインクのうち基準の近くにある割合、「描き漏らさない」= 基準のインクのうちこちらの近くにある割合。
   文字は、MuPDF が取り出した語のうち、こちらの文字に現れる割合。
   **結果（py-pdf/sample-files などの 38 ファイル・47 ページ）: 余計に描かない 92.1%・描き漏らさない 94.8%・文字の語 95.3%**。
   読めなかった 2 つは、ページの無い PDF（MuPDF も 0 ページ）と暗号化した PDF
2. **試験**（`program/tests/js/pdf.test.mjs`）: 字句・符号化・壊れた相互参照・CMap・ページの中身（線・曲線・破線・文字・画層）を、
   試験の中で組み立てた小さな PDF（`pdf-fixture.mjs`）で確かめる。同梱のサンプルの PDF は、全てのページを壊れた図形なしで描けること

```sh
git clone --depth 1 https://github.com/py-pdf/sample-files            # 評価の題材（CC BY-SA 4.0）
node program/tools/pdf-check.mjs --pages 2 --out 比べた画像 sample-files  # pip install pymupdf
```

## 7. PDF の 3D（U3D）

3D の注記（`/Subtype /3D`。または RichMedia の埋め込みのファイル）から、3D のデータ（U3D・PRC）を取り出す。U3D を読み、

### 7.1 読めるもの

- 最初の視点: PDF の既定の視点（`/3DV`）が U3D の視点の名前を指せばその視点、行列（`/C2W`）ならその向き、無ければ U3D の

## 8. Jw_cad の図面（.jww）

Jw_cad（日本の建築でよく使う無料の 2D CAD）の図面。中身は MFC の CArchive（リトルエンディアン）で、先頭の印 `JwwData.`・版の番号
（例 700 = Jw_cad 7.00 以降の形式）・見出し（用紙・画層グループ・画面の色・線種）・図形の一覧・ブロックの定義の一覧が並ぶ。
公開されている形式の説明と、ezjww（MIT）の説明書・試験の素材を手がかりに自前で書いた（コードは写していない）。

### 8.1 読めるもの

- 見出し: 用紙（A0〜A4・2A〜5A・10m〜100m）・16 の画層グループ × 16 の画層の名前・状態（非表示）・グループの縮尺・画面の色（線色 1〜9 と
  SXF の色 100〜356）・線種の模様（線種 2〜8・倍長の 16〜19・SXF の 30〜62）。版 700 は見出しを順に読み、ほかの版は図形の一覧の
  最初のクラスの印（`CData…`）を探して読み始める
- 図形: 線・円・円弧・楕円（傾き・扁平率）・点・文字（書体・大きさ・字間・角度）・ソリッド（四角・三角・RGB の色）・円の塗り（円・
  扇形・弓形・輪）・ブロック（入れ子）・寸法（寸法線・文字・補助線）。クラスとオブジェクトの番号は、ファイル全体で 1 つの表で数える
  （ブロックの定義の中の図形も同じ表）
- 図面のモデルへの変換（`cad2d/from-jww.js`）:
  - 座標は用紙の mm（用紙の中心が原点）のまま、用紙の大きさの紙のレイアウト 1 つに全ての図形を置く
  - 画層は「グループ-画層 名前」（例「0-1 寸法」）。状態 0 の画層・グループは隠す（画層の一覧から表示できる）
  - **実寸**: 画層グループの縮尺（1/S）を画層に持たせる（`layer.scale`）。指した図形の長さは実寸（用紙の mm × S）で出し、縮尺を添える。
    文字の高さは用紙の mm のまま（Jw_cad と同じ）。右の欄の「縮尺」と見出しバーに、使っている縮尺を並べる
  - 色: Jw_cad の**画面の色**（見出しの色）。地の色の反対の色（白地の黒）は前景色にする（暗い表示でも読める）
  - **補助線**（線種 9。印刷しない線）は、画層グループごとの「補助線（印刷しない）」の画層にまとめる。Jw_cad の画面と同じ色
    （255, 128, 255）・点線。Jw_cad の DXF の書き出しも、補助線を専用の画層（ADD_LINE）に分ける
  - Jw_cad が内部の設定を書いた文字（`Printer_PaperSize = 0` など。用紙の外 (0, −1000) の長さ 0 の文字）は描かない
  - 円の塗りの輪: 線種 105 は内側の楕円が外側と相似、106 は帯の幅が一定（内側の短い半径も同じ幅だけ小さい）

### 8.2 確かめ方（評価関数）と結果

1. **Jw_cad 自身の DXF と突き合わせる**（`program/tools/jww-check.mjs`。比べ方は試験と共用）: 同じ図面を、こちらの読み取りと、

   （0.05 mm）にあるかの割合を数える。Jw_cad の DXF は用紙の左下が原点で、画層グループ 0 の縮尺を掛けた長さ（実寸）で書くので、
   JWW の座標をずらして縮尺を掛けて比べる。文字は、同じ文字列が近い位置にあるか。題材は ezjww の、Jw_cad 10.02 で保存し直した図面と
   その DXF の 11 組（`tests/fixtures/drawings/jww/`）。**結果: 9 組は余計に描かない・描き漏らさない ともに 100%、文字も全て一致**。

     輪の内側の大きさは、Jw_cad の画面の絵（ezjww の `solid_reopened.png`）を測って確かめた（106 の内側の短い半径 ≈ 5 mm）
   - 文字: `text_auto_end` の DXF は日本語が「???」になっている（DXF の中身がそう。Jw_cad の書き出しの都合）
2. **Jw_cad の画面の絵と見比べる**: ezjww に Jw_cad の画面の絵（線色・線種・補助線・塗り）があるので、アプリで開いた画面と見比べた。

   線種）・補助線の画層・内部の設定の文字・実寸の読み出し・塗りの形・文字の角度・寸法・ブロック・Shift_JIS の DXF の文字コードの推測

## 9. SXF の図面（.sfc・.p21）

SXF は、国土交通省の電子納品で使う CAD の図面の形式（建設情報標準化委員会の SXF Ver.3.x）。同じ図面を 2 つの書き方で書ける:

- **SFC**（.sfc）… ISO 10303-21 の外枠の DATA 部に、注記 `/*SXF … SXF*/`（Ver.3 で増えたものは `/*SXF3 … SXF3*/`・`/*SXF3.1 …`）として
  「`#番号 = 名前_feature('引数', …)`」を並べた簡易形式。見出しの FILE_DESCRIPTION が `'SCADEC level2 feature_mode'`。日本の CAD の多くは Shift_JIS で書く
- **P21**（.p21）… ISO 10303-21 の AP202（ASSOCIATIVE_DRAUGHTING）の実体。FILE_DESCRIPTION が `'SCADEC level2 AP202_mode'`

ezsxf（MIT）の説明書・試験の素材を手がかりに自前で書いた（コードは写していない）。

### 9.1 読めるもの

- **フィーチャの並び**（SFC）: 図形は順に「入れ物」にたまり、次の 3 つが入れ物を閉じる。
  `composite_curve` … たまった図形が 1 本の複合曲線（ハッチングの境界。番号は出てきた順）、`sfig_org` … 複合図形（部分図・作図グループ・部品・
  属性の図形 `$$ATR…`）、`drawing_sheet` … 用紙そのもの。複合図形は `sfig_locate` が名前で置く（位置・角度・縦横の尺度）
- **表**はファイルのどこにあってもよい（実物は用紙の後に画層を書く）ので先に全てを読む: 画層は出てきた順に 1 から、色は既定の 16 色が名前で
  1〜16・利用者の色が 17 から、線種は既定の 15 種が名前で 1〜15・利用者の線種が 17 から、線幅は既定の 9 つ（0.13〜2.0 mm）がその番号・ほかが 11 から、
  文字の書体は出てきた順に 1 から
- 図形: 線・折れ線・円・円弧（向き）・楕円・楕円の弧・スプライン・クロソイド・文字（基準点 1〜9・幅に合わせる・傾き）・点の記号・外部の記号・
  寸法（長さ・弧長・角度・半径・直径。補助線・矢印 11 種・文字）・引出線・バルーン・ハッチング（外部定義・塗り・模様の線・タイル）
- **P21**（`sxf/p21.js`）: AP202 の実体（表の実体・STYLED_ITEM の見た目・TRIMMED_CURVE の線と円弧・POLYLINE・ELLIPSE・BEZIER と
  B スプライン・TEXT_LITERAL_WITH_EXTENT・矢印の DEFINED_SYMBOL・ANNOTATION_FILL_AREA・DRAUGHTING_SUBFIGURE_REPRESENTATION と MAPPED_ITEM・
  PRESENTATION_LAYER_ASSIGNMENT・INVISIBILITY）を、SFC と同じフィーチャの並びに直す。寸法は呼び出し（DRAUGHTING_CALLOUT）の中身を 1 つの寸法に
  まとめる（関係 DIMENSION_CALLOUT_RELATIONSHIP の related の側は、同じ文字をもう一度持つだけなので描かない）
- 図面のモデルへの変換（`cad2d/from-sxf.js`）:
  - 座標は用紙の mm（左下が原点）。用紙の大きさの紙のレイアウト 1 つ（A0〜A4 の横・縦、自由な大きさ）。複合図形はブロック、置く場所は INSERT
  - **部分図の縮尺**: 部分図は実寸で書き、置く尺度（例 0.05 = 1:20）で用紙に縮める。右の欄と見出しバーに「部分図の縮尺」を出す
  - **用紙の大きさで決まるもの**（線種のピッチ・矢印）は、部分図の中では縮尺で割った長さにする（1:20 の部分図の線種は 20 倍の長さで書く）
  - 黒と白（色 1・8）は前景色（白地の黒・黒地の白）。CAD の地の色に合わせて白で書いた図面も読める
  - 画層の番号 0（どの画層にも属さない。部分図を置く場所の多く）は「画層なし」
  - 図面の属性（`drawing_attribute`: 事業名・工事名・図面名・縮尺など）と属性の図形（`$$ATRU$$番号$$図形$$属性$$値`）は、図面のモデルに持たせる
- 画層の一覧（全ての形式で共通）: ブロック（SXF の部分図・寸法の中身）の中の図形も、その画層に数える。部分図の外形線・中心線なども、
  画層の一覧から表示・非表示を切り替えられる

- **線種のピッチ**: ezsxf が SXF Ver.3.1 の共通要素の仕様から引いたとする値（実線・破線 6/1.5・一点鎖線 12/1.5/0.25/1.5 など。用紙の mm）を使う。原典では確かめていない
- **スプライン**: 点の数が 3n+1 なら 3 次のベジェ曲線の制御点（ezsxf の読み。P21 の BEZIER_CURVE と一致する）、そうでなければ点を通る 3 次の曲線にした。
  SFC の仕様での意味は確かめられなかった（**分からない**）
- **クロソイドの向きの印**（0・1）の意味、**縦書きの文字**（向き 2。横に倒して描き、まだ描かない図形として知らせる）
- 外部定義の記号（置く点だけ）・外部定義のハッチングとタイルのハッチング（境界だけ）・属性の図形が指す外部のファイル（SAF）・ラスターの画像
- 複合図形の置き場所の画層（0 以外）が、中の図形の画層を置き換えるか（ezsxf はそう読む。こちらは中の図形の画層のまま）
