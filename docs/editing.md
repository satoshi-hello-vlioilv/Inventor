## 2. A: 3D の変換データの寸法を直す（`convert/dimensions.js`）

### 2.1 直し方

寸法 1 つを変えたとき、ほかの形をどう保つかを 1 つの規則で決める:
**断面の点の集まり S を向き v へ動かす。S に片方の端だけ入る部分が「v と平行な直線」だけなら、全ての角度が保たれる**
（伸び縮みするのは v と平行な直線だけ）。そうでなければ、その直し方はしない（理由を添えて断る）。

| 寸法 | S と v |
|---|---|
| 直線の長さ | 直線の終点から先の全ての点（穴も）を、直線の向きへ。できなければ、始点から手前の点を逆向きへ |
| 回転体の直径 | その円筒（同じ半径の軸方向の辺）の点だけを、半径の向きへ（半径方向の辺の長さは直径で直すので出さない） |
| 穴・円の直径 | 円の半径だけ |
| 角の丸み | 両側の直線に接したまま半径を変える（接点が直線の上を動く） |
| 外形の幅・外径 | 断面を相似に拡大・縮小（押し出しは外形の中心、回転体は軸の上を中心に） |
| 厚さ・回転の角度・面取り | その値だけ（面取りは厚さの半分より小さく。ビルダーの決まり） |

直した後に、作れる形かを確かめる（ループが閉じている・自分と交わらない・穴が外周の内でほかの穴の外・軸をまたがない・面取りが入る）。
体積と表面積の期待値を作り直し、厳密な面で書けない形（面取り付きの押し出しなど）は STEP 用の閉じた三角形を作り直す。
三角形は表示と同じ作り方（`preview.js` の `solidMesh`。同じ位置の頂点を 1 つにまとめる）。これに合わせて、**表示にも面取りを描くようにした**
（面取りで途中から消える辺は、消える深さで区切った帯にする。直線の部分の面取り面は平らな四角形になり、厳密）。

### 2.2 確かめ方（評価関数）と結果

`program/tools/spec-edit-check.mjs`（試験 `dimensions.test.mjs` と共用）: 変換データの全ての部品の全ての寸法を ±10% 変えてみる。

- 直せた寸法: その値になった・作れる形・閉じた三角形（細かく 1024 分割）の体積と表面積が厳密な期待値と 1e-4 以内・
  元の値に戻すと元の断面に戻る
- 直せなかった寸法: 理由を数える

**結果（試験の変換データ 6 つ・部品 44）: 388 を試し、275 を直せた・誤り 0**。直せなかった 113 の内訳は、隣の斜めの辺の角度が変わる 80、
回転の角度が 360° を超える 13、円弧の形が保てない 10、辺が無くなる 4、両側が直線でない丸み 4、穴が外周と交わる 2。

別の実装での確かめ（直した 275 個の変換データ。`--out` で書き出す）:

- **Python のビルダー**（`python -m ipt_build --dry-run`）: 全て受け付け、期待値の再計算（Python の独立した式）とアプリの値が全て一致
- **STEP**: Python で書き（`write_step`）、アプリの STEP の読み取りで読み戻した体積が期待値と最大 0.20% 差（曲面を三角形に分ける弦の誤差。
  球面の 3 つは表示が未対応なので除く）

```sh
node program/tools/spec-edit-check.mjs program/tests/fixtures/builder/*.inventor.json             # 全ての寸法を ±10%
node program/tools/spec-edit-check.mjs --out 置き場 program/tests/fixtures/builder/*.inventor.json  # 直した変換データを書き出す
```
