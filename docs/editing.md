## 2. A: 3D の変換データの寸法を直す（`convert/dimensions.js`）

### 2.1 直し方

寸法 1 つを変えたとき、ほかの形をどう保つかを 1 つの規則で決める:
**断面の点の集まり S を向き v へ動かす。S に片方の端だけ入る部分が「v と平行な直線」だけなら、全ての角度が保たれる**
（伸び縮みするのは v と平行な直線だけ）。そうでなければ、その直し方はしない（理由を添えて断る）。

| 寸法 | S と v |
|---|---|
| 直線の長さ | 直線の終点から先の全ての点（穴も）を、直線の向きへ。できなければ、始点から手前の点を逆向きへ |
| 回転体の直径 | その円筒（同じ半径の軸方向の辺）の点だけを、半径の向きへ（半径方向の辺の長さは直径で直すので出さない） |
| 穴・円の直径 | 円の半径だけ |
| 角の丸み | 両側の直線に接したまま半径を変える（接点が直線の上を動く） |
| 外形の幅・外径 | 断面を相似に拡大・縮小（押し出しは外形の中心、回転体は軸の上を中心に） |
| 厚さ・回転の角度・面取り | その値だけ（面取りは厚さの半分より小さく。ビルダーの決まり） |

直した後に、作れる形かを確かめる（ループが閉じている・自分と交わらない・穴が外周の内でほかの穴の外・軸をまたがない・面取りが入る）。
体積と表面積の期待値を作り直し、厳密な面で書けない形（面取り付きの押し出しなど）は STEP 用の閉じた三角形を作り直す。
三角形は表示と同じ作り方（`preview.js` の `solidMesh`。同じ位置の頂点を 1 つにまとめる）。これに合わせて、**表示にも面取りを描くようにした**
（面取りで途中から消える辺は、消える深さで区切った帯にする。直線の部分の面取り面は平らな四角形になり、厳密）。

  元の値に戻すと元の断面に戻る
- 直せなかった寸法: 理由を数える

## 4. B: Inventor で直せる部品（`convert/parametric.js`・`ipt_build/inventor.py`）

ビルダーが作る部品（押し出し・回転体）に、スケッチの拘束・寸法と名前つきの値（ユーザー パラメータ）を付け、Inventor の「パラメータ」で
値を変えると形が変わるようにした。名前は寸法の欄（A）の id と同じ（D1.0 → `D1_0`）。押し出しの長さ `t`・回転の角度 `a`（360° 未満）・
面取り `C0` `C1` …（面取りごとに 1 つのフィーチャ）・穴の位置 `P1X` `P1Y` … も名前つきの値。
寸法の欄では、各寸法の名前の横にこの名前の札を出す（参照寸法は「参照」、対応の無い寸法は「—」。`inventorNames`。画面の決め方は [ui.md](ui.md) §21）。

### 4.1 拘束の選び方（アプリ。変換データの版 4 の `parametric`）

断面の点・円弧の中心・円の半径を変数にし、拘束 1 つを「0 になる式」1 本で表す。候補を下の順に並べ、式の勾配がそれまでの拘束と
独立なものだけを採る（重なる拘束は Inventor で「拘束が多すぎる」になる）。形ごとの場合分けはしない。

1. 円弧の両端が中心から同じ距離（Inventor の円弧が元から持つ式）
2. 幾何拘束: 水平・垂直・平行（斜めの辺）・接線（直線と円弧・円弧どうし）。次に、まだ向きが決まらない直線の角度（前の直線から）
3. 寸法の欄の寸法: 丸み → 直径 → 長さ。直せる寸法を順に駆動の側にし、それを寸法の欄で直したときに**一緒に変わる寸法**
   （`companions`: 平行な相手の辺・丸みに接する直線）を参照寸法（後ろ）へ回す。採れなかった寸法は参照寸法（値を見せるだけ）
4. 位置: 原点からの横・縦の距離（外周の最初の点・穴の中心）。0 なら原点の軸の上（一致の拘束）
5. まだ自由度が残れば、点の位置

回転体の直径は、原点からの横の距離に「直径 / 2」の式で付ける。計画は変換データを作るとき・読むとき・寸法の欄で直したときに作り直す
（断面に合った計画にする）。

### 4.2 ビルダー

名前つきの値 → 断面 → 幾何拘束 → 寸法拘束（駆動寸法のパラメータに式）→ フィーチャ（値の式）の順に付ける。付けられない拘束・寸法が
あっても形は数で作り、`build-report.json` の `parametric` と知らせに数と最初の理由を残す。版 3 までの変換データは今までどおり（拘束なし）。

### 4.3 確かめ方（評価関数）と結果

`program/tools/parametric-check.mjs`（試験 `parametric.test.mjs` と共用）: 部品ごとに、完全拘束（自由度 0）・今の値で解いても形が動かない
（0.0001 mm 以内）・名前が Inventor で使える・式の名前がある。名前つきの値を ±10% 変えて拘束を解いた形（ニュートン法。完全拘束なら解は 1 つ）と、
寸法の欄の直し方（`applyDimension`）の形を比べる（位置の違いは除く）。

| 変換データ | 部品（計画） | 問題 | 直したとき 同じ | 違う | 解けない |
|---|---|---|---|---|---|
| 試験の変換データ 6 つ | 44（32） | 0 | 49 | 9 | 0 |
| 寸法の欄で直した 275 個（`spec-edit-check.mjs --out`） | 275（275） | 0 | 492 | 169 | 0 |
| 取り込んだ HTML の全て（`tests/fixtures/html` の 15） | 111（97） | 0 | 151 | 54 | 0 |

「違う」は、平行な辺が 3 組以上の形（六角形・八角形）と段のある回転体（スペーサー）。寸法の欄は直すたびに伸び縮みする辺を選ぶが、Inventor の拘束は
どの寸法を参照にするかが 1 つに決まるので、全ての寸法で同じにはできない（例: 八角形は 8 辺のうち 2 辺が参照寸法になり、残り 6 辺のうち 4 辺で違う）。
その場合も Inventor で解ける（解けない 0）。

擬似 Inventor（`tests/fake_constraints.py`）は、拘束・寸法の式を**アプリとは別に**実装し、付けるたびに「今の形に合うか」「ほかと重ならないか」を
数値の勾配の階数で確かめて、合わない・重なる拘束を断る（本物の Inventor と同じく）。寸法のパラメータに式を入れると、その値が今の寸法と同じか確かめる。
試験の変換データの全部品で、名前つきの値・拘束・寸法が 1 つも断られず、自由度 0（完全拘束）になる（`test_builder.py` の `ParametricTest`）。
取り込んだ HTML の全て（計画のある 97 部品・名前つきの値 252）でも、擬似 Inventor で断られた拘束 0・自由度 0。
付けられない寸法があっても形は作る・名前つきの値を作れなければ数で作る・版 3 は拘束なし、も確かめた。

## 5. D: 図面を DXF で書く（`formats/cad2d/to-dxf.js`）

読んだ図面（DWG・DXF・Jw_cad・SXF・PDF。共通のモデル `formats/cad2d/model.js`）を DXF に書く。直していない図面も、ほかの形式から DXF に直して渡せる。

| 版 | 文字 | 向き |
|---|---|---|
| R2013（AC1027。既定） | UTF-8 | AutoCAD 2013 以降・Inventor・BricsCAD・LibreCAD など |
| R2000（AC1015） | Shift_JIS（ANSI_932）。Shift_JIS に無い文字は `\U+XXXX`、4 桁に収まらない文字（𠮷 など）は ? | 古い CAD・Jw_cad など（日本語の AutoCAD が R2000 で書く形） |

### 5.1 書ける形に整える（`prepareForDxf`。読んだ形式に関わらず同じ規則）

- 名前（画層・線種・文字スタイル・ブロック）: AutoCAD で使えない文字（`< > / \ " : ; ? * | = \``）を `_` に。大文字・小文字だけ違う名前は番号で分ける。
  参照（図形の画層・ブロック参照のブロックなど）も付け替える。AutoCAD の系の画層（`*ADSK_…`）の先頭の `*` は残す
- レイアウト: モデルは `*Model_Space`、紙のレイアウトはタブの順に `*Paper_Space`・`*Paper_Space0` …。モデルの無い図面（Jw_cad・SXF・PDF）は
  空のモデルを足し、開くと紙のレイアウトが出る（`$TILEMODE` 0）
- ハンドル: 元の番号を残し、無い・16 進でない（PDF の `1.A` など）・重なるものに新しい番号。`$HANDSEED` は全ての番号より大きい
- 参照されているのに表に無い画層・線種・文字スタイルは足す。線の太さは AutoCAD の決まった値（0・5・9・13 … 211）の近いものに
- DXF に同じ図形が無いもの: パス（PDF の線と塗り・Jw_cad の塗り・SXF の矢印）は、塗り → 塗りつぶしのハッチング、線 → 直線だけならポリライン・
  曲線を含めば同じ曲線の 3 次スプライン（ベジェと同じ曲線。直線の区間は 1/3・2/3 の点を制御点に）、破線 → 模様ごとの線種（`DASH_1` …）。
  弧の長さの寸法（SXF）は、見た目のまま平行寸法として
- 書かないもの（数えて知らせる）: 3D の立体（ACIS）・画像（DXF では別のファイルが要る）・値の壊れた図形・無いブロックを参照する図形。
  画層の縮尺（Jw_cad）は DXF に無いので書かない（長さは図面の長さのまま）。外部参照はふつうのブロックとして書く

保存した後の知らせに、書かなかったもの・直して書いたもの・名前を変えたものを出す（`dxfNotes`）。

### 5.2 確かめ方（評価関数）と結果

- `program/tools/dxf-write-check.mjs`（試験 `dxf-writer.test.mjs` と共用）: 読む → 書く → 書いた DXF をアプリの読み取りで読み直し、整えた写しと
  突き合わせる。図形はハンドルで全ての値（`cad2d-compare.mjs` の `compareDrawings`）、表（画層・線種・文字スタイル）・ブロック・レイアウト・単位・
  線種の尺度は名前で（`compareTables`）

## 6. D: 図面を直す（`formats/cad2d/transform.js`・`edit/drawing.js`）

### 6.1 動かし方

図形を相似の変換（回転・平行移動・拡大。鏡映は除く）で動かす。円・円弧・ポリライン・文字・ブロック参照・ハッチング・塗りは押し出しの向きの座標系
（OCS）の値を持つので、変換を OCS に移してから当てる（押し出し −Z の図形は OCS の X が図面の −X で、角度の向きも逆）。時計回りのハッチングの円弧の辺は
角度を補角で持つので、回す向きも逆。寸法は種類ごとに意味のある定義点だけを動かし、見た目の無名のブロック（`*D…`）の図形も同じ変換で動かす。
押し出しの向きが Z と平行でない図形（立てた面の文字など）・ビューポート・3D の立体は直さない（理由を返す）。

命令（`DrawingEdits`）: 動かす・写す（寸法は見た目のブロックも写す）・回す・消す（取り消すと元の順番の場所へ）・画層を変える・文字を直す。
取り消し・やり直しは `edit/history.js`。図形のオブジェクトは差し替えずに中身を入れ替える（選んでいる図形が直した後も同じ図形を指す）。
全ての図形を先に計算してから当てる（1 つでも直せなければ何も変えない）。ロックした画層の図形・レイアウトに直に置かれていない図形は直さない。

### 6.2 確かめ方（評価関数）と結果

`program/tools/edit2d-check.mjs`（試験 `edit2d.test.mjs` と共用）: 図形を変換で動かして描いたもの（`viewer2d/scene.js`）と、元の描画を同じ変換で
動かしたものが一致するか。描く側の計算を通すので、直す側と独立に確かめられる。変換は 3 つ（移動・回転 30°・回転＋2 倍＋移動）。
曲線は描く側が刻むので（円はいつも角度 0 から刻む）、文字・点・開いた線の端は一致、ほかの点は相手の折れ線から区間の長さの 10% の内を合うとする。

- サンプルと試験の図面: 17,904 / 17,904 が一致。ACadSharp の試験の図面 50 枚: 9,120 / 9,120。LibreDWG の試験の図面 153 枚: 9,430 / 9,432
  （合わなかった 2 つは立てた面の複数行の文字。直さない図形にした）。模様のハッチングは、境界にちょうど触れる破線が丸めで出入りするので 5% まで許す
- サンプルに無い向きの図形（押し出し −Z の円・円弧・ポリライン・文字・ブロック参照・塗り・ハッチング、時計回りの円弧・楕円弧の辺）は試験の中で作る。
  わざと入れた誤り（OCS を無視・時計回りの向き・文字の角度・楕円の辺の向き）を、この図形で全て検出することを確かめた
- 命令: 動かす・回す・写す・消す・画層・文字を続けて行い、取り消すと各段階の図面にぴったり戻り、やり直すと直した後に戻る。直した図面も DXF に書いて
  読み直すと一致する。直せないときは何も変えず、取り消しの列にも入らない
