# 画面の設計: 改良案の比較と、選んだ形

2026-10 に画面を作り直したときの記録。何が使いにくかったか（測った値）、改良案 6 案と複合案 5 案の点数、選んだ形、作り直した後の測定。

## 1. 作り直す前に測ったこと

`program/tools/ui-check.mjs` で、利用者の画面と同じ大きさ（2160×1440・表示倍率 125% → 1728×1152）で状態ごとに撮り、迷いやすさに関わる量を測った
（窓の代わりは `program/tools/ui_server.py`。作る仕事は段階を手で進められる）。状態は 10 通り（起動・何も開いていない・サンプルの一覧・部品・組立・
three.js の HTML・変換データ・ライブラリを尋ねる・作っている途中・作り終えた）× ライト・ダーク。

| 見えた問題 | 測った値（作り直す前・ライト） |
|---|---|
| どれを押すか迷う: 塗りの主ボタンが同時に 2〜3 個（「ファイルを開く」が常に主） | HTML 3 個・変換データ 2 個・尋ねる 3 個・作っている途中 2 個 |
| 作り始めると、中止・結果が欄の下へ流れる | 右の欄のスクロールしないと見えない高さ: 作っている途中 1,910px・作り終えた 1,919px。中止ボタンの上端 1,070px（画面の下端近く） |
| いまどの段階か（取り込んだ・単位は確かめた・作った・照合した）が見えない | 段階の表示なし |
| 起動のたびに一覧のモーダルが出て、読む量が多い | 起動時に見える操作 18 個（ほか 15 個はスクロールの先）・文字 989 字 |
| 説明の文が常に出ている | HTML のとき右の欄の文字 906 字 |
| 文字の大きさがばらばらで、見出しが弱い | 文字の大きさ 7〜9 種類・最小 11px |
| 読みにくい色 | コントラスト比の最小 4.31（「サンプル」の印。WCAG の 4.5 未満） |
| 組立で部品が足りないとき、次にすることのボタンが無い | 次の行動の部品なし（一覧の文を読んでドロップするしかない） |

## 2. 比べ方（評価関数）

7 つの基準を 10 段階で採点し、重みを掛けて 100 点満点にする（`program/tools/ui_score.py`。重みは利用者の言葉「迷わない・視覚化・見栄え」から）。

| 基準 | 重み | 見るところ |
|---|--:|---|
| 次の行動がすぐ分かる | 20 | 主のボタンが 1 つで、いつも同じ場所にあるか（探させない・推測させない） |
| 状態と進み具合が見える | 15 | いまどの段か・作る仕事の進み・結果の良し悪しが、読まずに色と形で分かるか |
| 読む量・判断の数が少ない | 15 | 常に出ている文・操作の数（Hick の法則） |
| どこに何があるかが一定 | 15 | 状態が変わっても、操作・結果の場所が動かないか（思い出させない） |
| 見栄え・視覚の階層 | 15 | 文字の大きさの段・余白・色の役割（青＝操作と進行、緑＝一致、琥珀＝確かめて、赤＝失敗） |
| 3D の見やすさ・操作の短さ | 10 | 3D の面積と、操作までの距離 |
| 作り直しの確かさ・保守性 | 10 | 今の仕組み（作る仕事・取り込み・3D）を壊さずに作れるか、部品が共通化されるか |

**僅差の決め方**: 各基準の採点に ±1 段階のぶれがあるとすると、1 案の合計のぶれは σ1 = √Σ(w/10)² = 3.87 点、2 案の差のぶれは σd = σ1·√2 = 5.48 点。
1 位と 2 位の差が 2σd = **11.0 点** 未満なら、採点のぶれで順位が入れ替わりうるので僅差とし、上位から複合案を作って 5 案で比べ直す。
それでも僅差なら、最も重い基準（次の行動）→ 作り直しの確かさ → 合計 の順で決める。

## 5. 選んだ形（E×B: 行動ドック ＋ 段階の帯）

| （HTML のときだけ）元のページ | 3D（主役） | 右の欄 |
|---|---|---|
| 元の three.js のページ。表示を選んで「この状態を取り込む」 | 形・寸法の強調・視点のボタン | 上: **段階の帯** ① → ② → ③ → ④<br>中: 中身（スクロール）<br>下: **行動ドック**（状態の一文・進み具合・主のボタン 1 つ・保存先） |

上端の見出しバーには、いま開いているもの（種類の印・名前・サンプルの印）と、「サンプル・受け取ったファイル」「ファイルを開く Ctrl+O」を置く。

- **主のボタン（塗りの青）は、どの状態でも 1 つまで**。どれにするかは `ui/flow.js` の `setNext(持ち主, 要素)` が決める
  （持ち主は「作る」と「見る」。作るほうが先）。選ばれた要素に `data-next` が付く（測る道具もこれを見る）
- **段階の帯**（`ui/steps.js`）: HTML は 取り込む → 単位を確かめる → 作る → 照合する、変換データは 開く → 中身を確かめる → 作る → 照合する。
  済み（緑の ✓）・いま（青）・進行中（回る輪）・確かめて（琥珀の !。単位を大きさから推定したとき）・失敗（赤）を色と形の両方で示す
  （色だけに頼らない）。段の下に一言（three.js r170・推定 1 mm・25 種類・下のボタンで・一致 25 / 25）。押すとその段の欄へ移り、単位なら欄を光らせて選ぶ所にフォーカスする
- **行動ドック**（右の欄の下端に固定）: 上の縁の色が仕事の状態（青: 進行中・緑: 一致・琥珀: 注意・赤: 失敗）。状態の一文 → 進み具合の棒 →
  主のボタン → 保存先。作り終えたら「保存先を開く」が主になり、作るボタンは「作り直す」の見出しの下に控えめに並ぶ。見えるものが無ければ帯ごと消える
- **照合の結果**は右の欄のいちばん上（ファイルの情報の次）に出し、一致・不一致・失敗・作成中・待ちの数を 1 本の帯（比率）で見せる
- **始め方**: 何も開いていなければ、3D の場所そのものに受け口・「ファイルを選ぶ」（主）・「サンプルで試す」と、2 つの使い道（見る／CAD にする 4 段階）。
  起動のたびのモーダルはやめた（サンプルの一覧は見出しバーから開く）
- **文字の段**: 12・13・14・16・19px の 5 段（`--fs-xs`〜`--fs-xl`）。段の名前は 7 字まで（帯の 1 段の幅 ≒ 7 字。折り返さない）

### 状態ごとの「次にすること」

| 状態 | 主のボタン（`data-next`） | 段階の帯 |
|---|---|---|
| 何も開いていない | ファイルを選ぶ（始め方の中） | 出さない |
| 部品（.ipt・STEP の部品）を見ている | なし（見るだけ。ファイルを開くは見出しバーに控えめに） | 出さない |
| 組立で部品が足りない | 見つからない部品を加える（2 種類） | 出さない |
| HTML を取り込めなかった | この状態を取り込む | ① 赤 |
| HTML・変換データで作れる | Inventor で作る（Inventor が無ければ STEP を作る） | ③ が青 |
| ライブラリが無い | 入れて作る | ③ が青 |
| 作っている途中 | なし（中止は控えめなボタン。押す必要が無いので主にしない） | ③ が回る輪・作った数 |
| 作り終えた | 保存先を開く | ③④ が緑（不一致は琥珀・失敗は赤） |

## 6. 作り直した後に測ったこと

同じ道具・同じ状態で、作り直す前（main）と後を測った（ライト。ダークも同じ傾向）。

| 状態 | 主ボタンの数 | 文字の大きさの種類・最小 | コントラスト比の最小 | そのほか |
|---|---|---|---|---|
| 起動 | 1 → 1 | 8 種類・11px → 5 種類・12px | 5.22 → 5.07 | 見える操作 18（＋スクロールの先 15）→ 4、文字 989 → 332 字 |
| 部品 | 1 → 0 | 9・11 → 4・12 | 4.31 → 5.07 | 右の欄のスクロールの先 171 → 0px |
| 組立 | 1 → 1 | 8・11 → 4・12 | 4.31 → 5.07 | 次の行動「見つからない部品を加える」が新たに見える位置に |
| HTML | 3 → 1 | 8・11 → 4・12 | 4.31 → 5.07 | 右の欄の文字 906 → 522 字、段階の帯あり |
| 変換データ | 2 → 1 | 8・11 → 4・12 | 4.86 → 5.07 | スクロールの先 1,353 → 1,109px（作る部品 25 種類の一覧） |
| ライブラリを尋ねる | 3 → 1 | 8・11 → 4・12 | 4.86 → 5.07 | 尋ねる文と「入れて作る」がドックの中に |
| 作っている途中 | 2 → 0 | 7・11 → 4・12 | 4.49 → 4.68 | 中止は常に見える（ドック）。段階の帯で「作る」が進行中 |
| 作り終えた | 2 → 1 | 7・11 → 4・12 | 4.49 → 4.68 | 「保存先を開く」の面積 4,035 → 13,452px²、照合の結果は欄の上端に帯で |

- **引き換えにしたもの**: 3D が画面に占める割合は 0.77 → 0.69 に下がった。右の欄を 312 → 388px に広げた（段階の帯の 4 段の名前・
  ドックの 2 つの作るボタン・照合の結果の行を、切らずに出すため）のと、3D の周りに余白を取ったため。3D はなお 1,290×1,060px ほどある
- 右の欄は、変換データ（作る部品 25 種類）のとき 1,100〜1,800px スクロールする。次にすることと仕事の状態はドックに固定し、
  照合の結果は欄の上端に置いたので、スクロールしなくても判断できる
- 窓の自己診断（`desktop/src/selftest.js`）は、作り終えた色を行動ドック（`#dock` の `data-tone`）で確かめる。WebKitGTK の窓で 19 項目すべて合格

## 7. 測り直し方

```sh
python program/tools/ui_server.py 8765          # 窓の代わり（http://127.0.0.1:8765/）。作る仕事は /__dev/freeze・/__dev/step?n= で進める
node program/tools/ui-check.mjs 出力フォルダ both  # 状態ごとの撮影（PNG）と測定（metrics.json）。Playwright（npm -g）と Chromium が要る
python program/tools/ui_score.py                  # 改良案の点数・僅差の判定・選んだ案
```
